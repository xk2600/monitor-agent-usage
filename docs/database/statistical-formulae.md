# Statistical Formulae & Metrics

This document details the mathematical models, formulas, and normalization algorithms utilized by Monitor Agent Usage to produce the time-series charts, KPI cards, and cache efficiency metrics.

---

## 1. 15-Minute Epoch Bucketing

To create an evenly spaced time-series grid regardless of when individual turns occur, every timestamp is mapped to a discrete 15-minute boundary:

$$\Delta t_{\text{bucket}} = 900 \text{ seconds} \quad (15 \text{ minutes})$$

For any Unix epoch timestamp $t$ (in seconds since UTC Jan 1, 1970):

$$b(t) = \left\lfloor \frac{t}{900} \right\rfloor \times 900$$

### Properties
- **Deterministic**: Any turn occurring between `17:00:00` and `17:14:59` UTC maps to the exact integer epoch corresponding to `17:00:00` UTC.
- **Provider Agnostic**: Turns from Claude, Grok, Codex, and Antigravity align onto the identical 15-minute interval coordinate.

```python
BUCKET_SECONDS = 900
bucket_15m_epoch = (timestamp_epoch // BUCKET_SECONDS) * BUCKET_SECONDS
```

## 2. Token Categorization & Total Consumption

Token counts are divided into four orthogonal metrics:

| Symbol | Metric Name | Definition |
|---|---|---|
| $T_{\text{in}}$ | **Tokens In** | Uncached prompt / input context tokens processed by the model. |
| $T_{\text{out}}$ | **Tokens Out** | Completion / response tokens generated by the model. |
| $T_{\text{cached}}$ | **Tokens Cached** | Input tokens served directly from the provider's prompt cache. |
| $T_{\text{cwrite}}$ | **Tokens Cache Write** | Tokens written to persistent cache during cache checkpoint creation. |

### Total Tokens
The total token consumption represents the sum of all four metrics:

$$T_{\text{total}} = T_{\text{in}} + T_{\text{out}} + T_{\text{cached}} + T_{\text{cwrite}}$$

## 3. Prompt Cache Hit Percentage ($\text{CacheHit}\%$)

Modern LLM APIs (Anthropic prompt caching, OpenAI prompt cache, Grok KV-cache) bill cached prompt tokens at a substantially lower rate (often a $50\%$ to $90\%$ discount). The **Prompt Cache Hit Percentage** quantifies how effectively prompts leverage cached context:

$$\text{CacheHit}\% = \begin{cases} 
\left( \dfrac{T_{\text{cached}}}{T_{\text{in}} + T_{\text{cached}} + T_{\text{cwrite}}} \right) \times 100 & \text{if } (T_{\text{in}} + T_{\text{cached}} + T_{\text{cwrite}}) > 0 \\ 
0.0 & \text{otherwise} 
\end{cases}$$

### Interpretation
- **$0\%$ Cache Hit**: Every prompt is evaluated from scratch with zero cache reuse.
- **$80\%-95\%$ Cache Hit**: Typical in multi-turn agent conversations (e.g. Claude Code or Antigravity) where the system prompt, codebase map, and prior conversation history are successfully reused.

## 4. Differential Turn Counter (Codex Rollouts)

OpenAI Codex rollouts report cumulative tokens across the entire session ($T_{\text{tot\_in}}$ and $T_{\text{tot\_out}}$) on periodic `token_count` events. To calculate per-turn increments $\Delta T$:

$$\Delta T_{\text{tot\_in}} = \max\left(0, T_{\text{tot\_in}}^{(k)} - T_{\text{tot\_in}}^{(k-1)}\right)$$

$$\Delta T_{\text{cached}} = \max\left(0, T_{\text{tot\_cached}}^{(k)} - T_{\text{tot\_cached}}^{(k-1)}\right)$$

$$\Delta T_{\text{out}} = \max\left(0, T_{\text{tot\_out}}^{(k)} - T_{\text{tot\_out}}^{(k-1)}\right)$$

Because Codex `input_tokens` includes cached tokens, the uncached input tokens $T_{\text{in}}$ for the turn are derived as:

$$T_{\text{in}} = \begin{cases}
\Delta T_{\text{tot\_in}} - \Delta T_{\text{cached}} & \text{if } \Delta T_{\text{tot\_in}} \ge \Delta T_{\text{cached}} \\
\Delta T_{\text{tot\_in}} & \text{otherwise}
\end{cases}$$

## 5. Continuous Time-Series Interpolation (Zero-Filling)

If a developer does not interact with any agent during a 15-minute block, the database contains no row for that epoch. Returning sparse points would cause bar charts to compress irregularly.

The zero-filling algorithm constructs a continuous time grid:

$$\text{Start Bucket: } B_{\text{min}} = \left\lfloor \frac{t_{\text{start}}}{900} \right\rfloor \times 900$$
$$\text{End Bucket: } B_{\text{max}} = \left\lfloor \frac{t_{\text{end}}}{900} \right\rfloor \times 900$$

For every discrete step $b = B_{\text{min}}, B_{\text{min}} + 900, \dots, B_{\text{max}}$:

$$\text{Bucket}(b) = \begin{cases} 
\text{Aggregated}(b) & \text{if } b \in \text{Database} \\ 
\{ T_{\text{in}}: 0, T_{\text{out}}: 0, T_{\text{cached}}: 0, T_{\text{total}}: 0, \text{CacheHit}\%: 0.0 \} & \text{otherwise} 
\end{cases}$$

## 6. Time Window Calculations

| Window Selection | Start Epoch ($t_{\text{start}}$) | End Epoch ($t_{\text{end}}$) | Maximum Buckets |
|---|---|---|---|
| **Last 6 Hours** | $t_{\text{now}} - (6 \times 3600)$ | $t_{\text{now}}$ | $24$ |
| **Last 24 Hours** | $t_{\text{now}} - (24 \times 3600)$ | $t_{\text{now}}$ | $96$ |
| **Last 3 Days** | $t_{\text{now}} - (72 \times 3600)$ | $t_{\text{now}}$ | $288$ |
| **Last 7 Days** | $t_{\text{now}} - (168 \times 3600)$ | $t_{\text{now}}$ | $672$ |
| **Last 30 Days** | $t_{\text{now}} - (720 \times 3600)$ | $t_{\text{now}}$ | $2880$ (sparse) |
| **All Historical** | $\min(t_{\text{event\_epoch}})$ | $\max(t_{\text{event\_epoch}})$ | Dynamic |
